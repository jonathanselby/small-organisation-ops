# Decision Register

A decision register preserves the reasoning behind material choices without turning meeting minutes into an archive project.

## Fields

| Field | Purpose |
|---|---|
| Decision | What was actually decided |
| Context | The problem or constraint that required a choice |
| Alternatives | Material options considered |
| Rationale | Why this option was selected |
| Owner | Person accountable for carrying the decision forward |
| Date | When the decision was made |
| Revisit Trigger | Condition that should cause the decision to be reconsidered |

## Record decisions, not discussions

Weak:

> Discussed roof quotes and agreed more information was needed.

That is meeting context, not a decision.

Better:

> Accept BrightBuild's fixed-price roof replacement quote, subject to permit approval.

The rationale can then record why that option was preferred and what would cause the choice to be revisited.

## Why the revisit trigger matters

Many decisions are correct only under a set of assumptions. Instead of pretending every decision is permanent, state the condition under which it should be reopened.

Examples:

- costs exceed the approved cap by more than 10%;
- legislation changes;
- membership exceeds 1,000;
- the selected supplier misses two consecutive service levels;
- a planned grant is not awarded.
