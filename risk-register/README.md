# Risk Register

A small risk register should make the risk understandable before it attempts to score it.

## Write the risk as a chain

```text
CAUSE
  |
  v
EVENT
  |
  v
CONSEQUENCE
```

A useful risk statement explains all three.

Example:

> Because the hall roof has deteriorated (**cause**), heavy rain may cause water ingress (**event**), leading to programme cancellation, property damage and unplanned repair cost (**consequence**).

This is more useful than “Roof risk — High”.

## Controls and residual exposure

```text
INHERENT EXPOSURE
       |
       v
    CONTROLS
       |
       v
RESIDUAL EXPOSURE
```

Controls are things already operating that reduce likelihood or consequence. Actions are future work intended to improve the position.

Do not list an action as though it were already a control.

## Fields

| Field | Purpose |
|---|---|
| Risk | Compact cause-event-consequence statement |
| Cause | Why the event could occur |
| Event | The uncertain event itself |
| Consequence | What matters if it occurs |
| Controls | Existing measures already operating |
| Residual Exposure | The practical exposure after current controls |
| Owner | One accountable person |
| Actions / Review | Next treatment action and/or review trigger/date |

## Exposure scale

A small organisation usually needs only a simple, shared vocabulary such as **Low / Medium / High**.

Do not introduce a 5×5 matrix unless it genuinely improves decisions. A false sense of numerical precision can make a weak risk statement look sophisticated without making it more useful.
